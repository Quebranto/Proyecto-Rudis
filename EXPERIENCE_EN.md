# 🌐 Project Rudis — Experience

**Language / Idioma:** **English** · [Español](./EXPERIENCE_ES.md)

> **Rudis should not feel like a repository that explains a future system. It should feel like the front door to a persistent institutional world.**

This page describes the **experience layer** of Rudis: what a person should understand, feel and be able to do before entering the full architecture or Corpus.

---

# 1. The first five minutes

A first-time visitor should be able to answer five questions quickly:

1. **Where am I?** — a persistent institutional ecosystem, not a single app or world.
2. **What can I do here?** — learn, build, participate, request help, inspect institutions, follow decisions and contribute.
3. **What persists when I leave?** — institutional state, provenance, decisions, obligations, evidence and continuity.
4. **Who is allowed to change what?** — only actors with demonstrated authority or competence for that effect.
5. **Why should I trust it?** — not because Rudis claims correctness, but because important claims are designed to be inspectable, challengeable and auditable.

```text
ENTER
-> ORIENT
-> SEE WHAT IS ALIVE
-> CHOOSE A PATH
-> ACT / OBSERVE
-> SEE CONSEQUENCES
-> RETURN TO A WORLD THAT CONTINUED
```

# 2. The home experience

The ideal Rudis home should not begin with documents. It should begin with **state**.

Conceptually:

```text
RUDIS TODAY

Habitability        stable
Infrastructure      nominal
Active incidents    0
Assembly             4 live matters
Evolutionary Palace 27 active pathways
Pioneer activity    6 contributions under review
Personal alerts     1
```

The exact values above are illustrative, not live production claims.

The important experience principle is:

> **The first thing Rudis shows is that something continues to exist even while you are away.**

`RUDIS != SESSION`

`WORLD CONTINUES != USER MUST BE ONLINE`

---

# 3. Choose what you came here to do

Instead of asking a visitor to understand the whole system, Rudis should offer clear intentions.

## 👁 Explore

See what Rudis is, how institutions fit together, what is currently active and what is still experimental.

## 🎓 Learn

Enter the Evolutionary Palace, explore educational pathways, simulations and capability development without confusing training with accreditation or destiny.

## 🛠 Build

See open Pioneer contributions, challenge suites, research tasks and authorized construction surfaces.

## 🏛 Participate

Follow Assemblies, public decisions, research rounds and institutional activity according to the visitor's actual status and rights.

## 🛡 Request help or protection

Find the Petitions / Pleas route, protection pathways and review mechanisms without requiring prior knowledge of institutional vocabulary.

## 💼 Evaluate / Invest / Partner

Enter a separate diligence route focused on thesis, product, maturity, evidence, boundaries, financing and staged review.

# 4. The core experience loops

Rudis becomes understandable when visitors see recurring loops instead of isolated institutions.

## Learning loop

```text
NEED / CURIOSITY
-> PATHWAY
-> LEARN
-> SIMULATE
-> PRACTICE
-> EVIDENCE
-> REVIEW
-> MORE OPTIONS
```

`LEARNING != AUTHORITY`

## Pioneer loop

```text
FIND OPEN WORK
-> CONTRIBUTE
-> PRESERVE PROVENANCE
-> TEST
-> COMPETITIVE DIGESTION
-> REVIEW
-> ACCEPT / REWORK / HOLD / REJECT
-> RECOGNITION WHEN JUSTIFIED
```

`CONTRIBUTION != SOVEREIGNTY`

## Institutional loop

```text
QUESTION / PROBLEM
-> EVIDENCE
-> RESEARCH
-> DELIBERATION
-> COMPETENT DECISION
-> IMPLEMENTATION
-> RECEIPT
-> AUDIT
```

`RESEARCH != LAW`

## Protection loop

```text
REQUEST / SIGNAL
-> INTAKE
-> PROVISIONAL PROTECTION WHEN AUTHORIZED
-> EVIDENCE
-> REVIEW / RESOLUTION
-> EXECUTION BY COMPETENT ORGAN
```

`PROTECT != POSSESS`

# 5. Make consequences visible

The strongest Rudis experience is not a beautiful world. It is a world where the user can understand **why something happened**.

When an action succeeds, Rudis should eventually be able to expose a human-readable causal receipt:

```text
ACTION
-> WHO REQUESTED IT
-> WHICH CLAIM / ROLE WAS USED
-> WHICH AUTHORITY WAS DEMONSTRATED
-> WHICH RULE APPLIED
-> WHICH MANDATE AUTHORIZED EXECUTION
-> WHAT EFFECT OCCURRED
-> WHERE THE RECEIPT / EVIDENCE LIVES
```

When an action fails, the experience should be equally explicit:

```text
DENIED
because:
CURRENT AUTHORITY COULD NOT BE DEMONSTRATED
```

rather than a generic error.

This is where StateOS becomes a user experience instead of only an architecture.

---

# 6. Show uncertainty honestly

Rudis should make uncertainty visible instead of hiding it behind confident UI.

Possible states include:

- **verified**;
- **provisional**;
- **stale**;
- **under review**;
- **disputed**;
- **research only**;
- **policy required**;
- **unresolved constitutional dependency**.

The interface should teach users that:

```text
UNKNOWN != FALSE
UNRESOLVED != AUTHORIZED
PROVISIONAL != PERMANENT
OLD != CURRENT
```

# 7. The investor experience

Investors should not receive the same experience with extra financial documents appended.

Their journey should be:

```text
PROBLEM
-> PRODUCT THESIS
-> LIVE EXPERIENCE MODEL
-> DIFFERENTIATION
-> CURRENT MATURITY
-> EVIDENCE
-> FAILURE MODES
-> DILIGENCE
-> FINANCING GATES
```

A useful investor should leave the first experience knowing:

- what StateOS changes;
- why Rudis Habitat makes that architecture visible;
- what is already testable;
- what is not production-ready;
- what could be financed;
- what evidence would falsify the thesis;
- what financing does and does not buy.

```text
CAPITAL -> CAPABILITY
CAPITAL != CONSTITUTIONAL AUTHORITY
```

---

# 8. Return value — why come back tomorrow?

A persistent ecosystem needs a reason to return.

A returning participant should be able to discover:

- what changed while they were away;
- which matters now affect them;
- what new opportunities exist;
- what contributions advanced;
- what research survived or failed;
- what institutions changed state;
- what requires their attention;
- what is still unresolved.

Conceptually:

```text
SINCE YOUR LAST VISIT

3 decisions changed state
1 contribution reached review
2 new learning opportunities
1 matter requires your attention
0 unresolved security alerts assigned to you
```

Again: illustrative experience model, not a claim of a current production feed.

The principle is:

> **Rudis should reward continuity of participation, not compulsive engagement.**

`RETURN VALUE != ENGAGEMENT TRAP`

---

# 9. Progressive disclosure

The public experience should have layers:

```text
LAYER 0 — LANGUAGE
LAYER 1 — WHY RUDIS EXISTS
LAYER 2 — WHAT YOU CAN DO
LAYER 3 — WHAT IS ALIVE
LAYER 4 — PRODUCT / INSTITUTIONAL EXPERIENCE
LAYER 5 — EVIDENCE / DILIGENCE
LAYER 6 — CORPUS / CANON
LAYER 7 — PURPOSE-BOUND RESTRICTED REVIEW
```

No first-time visitor should need Layer 6 to understand Layer 1.

---

# 10. Current reality

Today, much of this experience is still represented through public documents, narratives, architecture and pre-D3 implementation rather than a finished unified product surface.

```text
EXPERIENCE MODEL = CLEARER
UNIFIED LIVE EXPERIENCE = NOT YET COMPLETE
PRE-D3 = ACTIVE
D3 OPEN = NO
PRODUCTION = NO
```

This distinction must remain visible.
