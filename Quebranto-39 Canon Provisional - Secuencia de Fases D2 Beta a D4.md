# QUEBRANTO-39 — CANON PROVISIONAL
## Secuencia de Fases: D2 Funcional / Beta Oficial -> D4

**Fecha:** 20 de septiembre de 2026  
**Estado:** `CANON PROVISIONAL VIGENTE / DECISIÓN DEL STRATEGOS FUNDACIONAL`  
**Autoridad de entrada:** decisión expresa del Strategos Fundacional.  
**Naturaleza:** sustitución parcial de la secuencia de madurez previamente operada en PRE-D3.  
**Objeto:** eliminar D3 como fase operativa separada y reorganizar la transición de Rudis desde D2 real, funcional y beta oficial hacia D4.

---

# I. DECISIÓN FUNDACIONAL

La secuencia vigente de fases queda establecida así:

```text
D2
-> D2 FUNCTIONAL
-> D2 OPERATIONAL
-> D2 OFFICIAL BETA
-> D4 READINESS
-> D4
```

Queda eliminado como requisito de transición:

```text
D3 AS A SEPARATE OPERATIONAL PHASE
```

No se requerirá una autorización independiente para "entrar en D3".

---

# II. PRINCIPIO RECTOR

D2 no equivale a simulación.

```text
D2 != SIMULATION
D2 != PROTOTYPE-ONLY
D2 = REAL FUNCTIONAL OPERATION WITH BOUNDED AUTHORITY
```

La Beta D2 podrá ser real, pública cuando proceda, funcional y operativa.

```text
BETA != FAKE
BETA != D4
PUBLIC != PRODUCTION
REAL != UNBOUNDED
```

---

# III. D2 FUNCTIONAL

D2 FUNCTIONAL existe cuando las cadenas esenciales funcionan de extremo a extremo de forma real y trazable.

Mínimo:

```text
REAL STATEOS PATH
+ REAL INTENT PATH
+ REAL RECEIPTS
+ REAL CURRENTNESS
+ REAL STOP / REVOCATION
+ REAL FRONTIER
+ REAL CONTRIBUTION ROUTING
+ REAL RETURN PATH
```

```text
FUNCTIONAL != COMPLETE
```

No exige escala de producción ni cierre de toda deuda técnica.

---

# IV. D2 OPERATIONAL

D2 OPERATIONAL existe cuando Rudis puede sostener de forma repetible sus funciones esenciales.

Requiere, dentro de su alcance:

- restart/recovery;
- failover;
- observability;
- rollback;
- deployment reproducible;
- actor wake-on-event;
- AssemblyOS routing;
- Institutional Mesh;
- Pioneer intake;

```text
FUNCTIONAL
!=
OPERATIONAL
```

La Beta D2 no implica por sí sola:

- autoridad R2;
