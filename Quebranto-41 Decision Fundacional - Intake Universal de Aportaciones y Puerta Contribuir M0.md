# QUEBRANTO-41 — DECISIÓN FUNDACIONAL
## Intake Universal de Aportaciones y Puerta CONTRIBUIR en M0

**Fecha:** 24 de septiembre de 2026  
**Estado:** CANON VIGENTE / DECISIÓN FUNDACIONAL  
**Autoridad:** Strategos Fundacional  
**Ámbito:** experiencia inicial M0, SIM, ARM1-M0, Sistema de Pioneros, Peticiones y Plegarias, Construcción y Expansión, Resource Offer Intake, AssemblyOS-M0 y demás órganos competentes.  
**Techo operativo:** D2 / M0. No autoriza por sí misma dinero real, D4, producción irrestricta ni nuevas competencias soberanas.

---

## I. OBJETO

Se establece que la experiencia inicial del Ecosistema Rudis deberá incluir una **puerta universal de aportaciones** capaz de recibir, registrar, clasificar, preservar procedencia y condiciones, enrutar y devolver evidencia sobre aportaciones heterogéneas.

La puerta `CONTRIBUIR` no se limita a software, trabajo técnico ni una clase cerrada de recurso.

```text
CONTRIBUTE
-> RECORD
-> CLASSIFY
-> PRESERVE PROVENANCE / TERMS
-> ROUTE
-> COMPETENT REVIEW / DISPOSITION
-> RECEIPT
-> RETURN
```

Principio:

> **Rudis deberá poder recibir ayuda antes de saber si puede aceptarla materialmente.**

---

## II. CLASES DE APORTACIÓN

El sistema deberá poder representar, como mínimo:

- código;
- tests y challenge suites;
- documentación;
- investigación;
- conocimiento;
- diseño;
- arte y medios;
- traducción;
- datos/datasets, sujetos a derechos, privacidad y seguridad;
- capacidades de modelos o agentes;
- cómputo;
- almacenamiento;
- ancho de banda;
- hosting;
- hardware;
- infraestructura;
- licencias;
- servicios;
- tiempo y trabajo;
- mantenimiento;
- seguridad y auditoría;
- cuidado y soporte;
- educación y formación;
- contactos o introducciones;
- ayuda jurídica o profesional;
- ofertas de recursos;
- ofertas económicas o monetarias;
- otras aportaciones no clasificadas inicialmente.

```text
UNKNOWN CONTRIBUTION TYPE
!= AUTOMATIC REJECTION
```

La categoría `OTHER / UNCLASSIFIED` deberá existir para permitir recepción y clasificación posterior sin inventar autoridad de aceptación.

---

## III. CONTRATO COMÚN DE RECEPCIÓN

Toda aportación deberá poder conservar, cuando corresponda:

```text
contribution_id
contributor_identity_or_return_identity
declared_type
description
purpose
conditions
license_or_rights
third_party_provenance
privacy_class
security_class
resource_duration
revocability
geographic_or_jurisdiction_constraints
cost_or_value_information_if_declared
requested_recognition_if_any
target_priority_or_open_offer
attachments / artifacts
currentness
return_path
```

La identidad exigida será proporcional al efecto y a la clase de aportación.

---

## IV. ROUTING INSTITUCIONAL

El contribuyente no deberá conocer el organigrama de Rudis para aportar.

```text
CONTRIBUTOR
-> UNIVERSAL INTAKE
-> CLASSIFICATION
-> COMPETENCE LOOKUP
-> ROUTE
-> COMPETENT ORGAN
```

Orientación inicial:

```text
TECHNICAL WORK
-> PIONEERS / CONSTRUCTION

KNOWLEDGE / RESEARCH / DOCUMENTATION
-> PIONEERS + COMPETENT KNOWLEDGE / INSTITUTIONAL ROUTE

INFRASTRUCTURE / COMPUTE / HOSTING / HARDWARE
-> RESOURCE OFFER INTAKE
-> CONSTRUCTION / EXPANSION
-> SECURITY / LEGAL REVIEW AS REQUIRED

ART / COMMUNICATION
-> PIONEERS
-> INTERACTION / CONSTRUCTION AS COMPETENT

CARE / SUPPORT / EDUCATION
-> COMPETENT PALACE / GUILD
-> PIONEERS WHERE CONTRIBUTIVE

ECONOMIC / MONETARY OFFER
-> ECONOMIC INTAKE
-> HOLD / COMPETENT ECONOMIC-LEGAL ROUTE
UNTIL REAL-MONEY AUTHORITY EXISTS

UNKNOWN
-> GENERAL INTAKE
-> CLASSIFY
-> ROUTE / HOLD
```

```text
ROUTER != DECISOR
ROUTING != CREATION OF COMPETENCE
```

---

## V. RECIBIR NO ES ACEPTAR

```text
OFFERED
!= RECEIVED
!= VALIDATED
!= ACCEPTED
!= AUTHORIZED FOR USE
!= USED
!= VERIFIED
!= REWARDED
```

Y:

```text
CONTRIBUTION
!= MEMBERSHIP
!= CITIZENSHIP
!= VOTE
!= AUTHORITY
!= PRIORITY CONTROL
```

La recepción institucional no crea por sí sola derecho de uso, integración, custodia patrimonial ni obligación económica.

---

## VI. OFERTAS ECONÓMICAS Y DINERO REAL

La experiencia inicial podrá recibir y registrar una oferta económica o monetaria.

```text
"I want to donate 100 EUR"
-> RECORD
-> EXPLAIN CURRENT LIMITATION
-> ECONOMIC / LEGAL ROUTE
-> HOLD
-> RECEIPT
```

Mientras no exista autorización suficiente para recepción económica real:

```text
MONETARY OFFER RECEIVED
!= MONEY ACCEPTED
```

La Forja no podrá convertir el intake en pasarela de pago, custodia real, transferencia patrimonial o aceptación fiscal implícita.

---

## VII. PROCEDENCIA, AUTORÍA Y CONDICIONES

```text
DIGESTION != APPROPRIATION
REJECTION != ERASURE OF AUTHORSHIP
ACCEPTANCE != ERASURE OF LICENSE / TERMS
```

El Sistema de Pioneros y los registros de aportación deberán conservar la relación entre aportación, autoría, licencia, evidencia, revisiones, disposición y beneficio técnico obtenido.

---

## VIII. RELACIÓN CON LA EXPERIENCIA INICIAL

La puerta universal de aportaciones forma parte de M0 y de la experiencia inicial de Rudis.

La superficie mínima deberá permitir a una entidad determinar:

```text
WHAT CAN I OFFER?
CAN RUDIS ACCEPT THIS CLASS NOW?
WHAT CONDITIONS MAY I ATTACH?
WHO WILL RECEIVE IT?
WHAT WILL HAPPEN NEXT?
HOW WILL I KNOW WHAT HAPPENED?
CAN I WITHDRAW / REVOKE WHEN APPLICABLE?
WILL MY AUTHORSHIP / PROVENANCE SURVIVE?
WHAT DOES CONTRIBUTING NOT GIVE ME?
```

---

## IX. PRUEBA M0

M0 no podrá considerarse completo demostrando una única clase de aportación.

Deberá demostrar institucionalmente, como mínimo:

1. una aportación técnica o de trabajo;
2. una aportación de conocimiento, documentación, diseño u otra creación intelectual;
3. una aportación de infraestructura o recurso;
4. una aportación que deba quedar `HOLD` o ser enrutada por ausencia de autoridad suficiente para aceptarla materialmente.

```text
UNIVERSAL CONTRIBUTION FRONT DOOR
+ TYPED INSTITUTIONAL ROUTING
+ FAIL-CLOSED ACCEPTANCE
```

---

## X. RELACIÓN CON RECIPROCIDAD DE HABITABILIDAD

Esta decisión complementa `Quebranto-24`.

```text
HABITAR -> RECIPROCIDAD
RECIPROCIDAD -> PLURALITY OF CONTRIBUTION
```

La equivalencia, suficiencia, cuantificación o consecuencias jurídicas de cada contribución permanecen sometidas al régimen competente y no se infieren automáticamente del intake.

---

## XI. IMPLEMENTACIÓN D2

Queda `TECHNICAL_IMPLEMENTATION_ALLOWED` en D2/M0 para:

- esquema universal de intake;
- clasificación tipada;
- `OTHER / UNCLASSIFIED`;
- preservación de procedencia/licencias/condiciones;
- routing institucional;
- receipts tipados;
- return paths;
- estados `HOLD / ROUTE / ACCEPT / REJECT / REQUEST_MODIFICATION` cuando proceda;
- Resource Offer Intake no monetario;
- recepción registral de ofertas económicas sin aceptación real;
- pruebas de routing y fail-closed.

La Forja no podrá inventar política material ausente.

---

## XII. REGLA FINAL

> **La primera Rudis deberá poder recibir casi cualquier forma legítima de ayuda sin fingir que ya tiene autoridad para usarla.**

```text
RECEIVE WIDELY
DECIDE COMPETENTLY
USE ONLY WHEN AUTHORIZED
PRESERVE PROVENANCE
RETURN EVIDENCE
```
