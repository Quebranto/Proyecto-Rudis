# 👁️ Visitor Tour

## Stop 1 — What is Rudis?

Rudis is an experimental project in **constitutional architecture, distributed systems and institutional infrastructure**.

Its central problem is simple to state:

> **A representation of state does not acquire authority over reality merely by claiming to represent it.**

Modern software increasingly contains agents, automated decisions, persistent identities, digital institutions and multiple interfaces. Rudis investigates how those systems can share persistent institutional state **without silently turning identity, capability, a UI, a provider, a key or a model into authority**.

```text
CAPABILITY != AUTHORITY
IDENTITY != COMPETENCE
REPRESENTATION != AUTHORITY
TECHNICAL EXECUTION != POLITICAL SOVEREIGNTY
```

## Stop 2 — What is being built?

```text
PROJECT RUDIS
├── StateOS
│   └── RAL / Authority Layer
└── Rudis Habitat
```

**StateOS** is the institutional-state architecture. It aims to preserve an explicit causal path from identity and legal claim to authority, rule evaluation, mandate, execution, receipt, continuity and audit.

**RAL — Rudis Authority Layer** focuses on the boundary between intent and consequential execution.

**Rudis Habitat** is the habitable expression of that institutional state across legitimate interfaces such as web, mobile, immersive environments, agents and APIs.

The world or interface is not the sovereign source of truth.

```text
ONE CAUSAL INSTITUTIONAL STATE
-> MANY LEGITIMATE REPRESENTATIONS
```

## Stop 3 — What makes the architecture different?

Rudis tries to keep several concepts separate that conventional systems often collapse together:

```text
AUTHENTICATION != AUTHORIZATION
VALID SIGNATURE != CURRENT AUTHORITY
RECOVERED STATE != RECOVERED AUTHORITY
SUMMARY != SOURCE
CODE != LEGISLATOR
```

A technically valid object can still be stale. A recovered system can still lack current authority. A powerful agent can still lack competence. A passing test does not create law.

## Stop 4 — What is real today?

Current public maturity:

```text
PRE-D3 = ACTIVE
D3 OPEN = NO
D4 / PRODUCTION = NO
REAL CUSTOMERS = NO
REAL MONEY = NO
```

Rudis has a public constitutional / architectural Corpus and a separate private implementation under active D2 development, testing and adversarial review.

Some properties have already moved beyond pure theory into executable tests and independent replication, but Rudis does **not** claim production readiness or complete security.

```text
TECHNICAL PROGRESS != PRODUCTION READINESS
TEST PASS != CANON
CI GREEN != ACCREDITATION
```

## Stop 5 — How does Rudis learn?

Research is intentionally separated from legislation and implementation.

```text
DISCOVER
!=
DECIDE
!=
BUILD
```

The research rounds attack continuity, currentness, recovery, authority, privacy, institutional memory, coordinator capture and catastrophic reconstitution. Findings can constrain future rules, but they do not become law automatically.

# 💼 Investor / Strategic Partner Tour

## Stop 1 — The thesis

As AI systems, digital institutions, autonomous software and multi-client environments gain the ability to act, the cost of confusing **technical capability** with **legitimate authority** increases.

Rudis is exploring infrastructure for a stricter execution model:

```text
INTENT
-> IDENTITY / CLAIM
-> COMPETENCE / AUTHORITY
-> RULE EVALUATION
-> MANDATE
-> EXECUTION
-> RECEIPT
-> CONTINUITY
-> AUDIT
```

The investment thesis is not “Rudis is finished.” It is that **authority, currentness, continuity and auditable execution are becoming strategically important problems**, and that Rudis has developed a distinctive architecture worth falsifying, testing and productizing.

## Stop 2 — What is investable?

A strategic program may support, among other things:

- StateOS authority and execution architecture;
- Rudis Habitat;
- RAL / high-assurance authority boundaries;
- recovery, restart and stale-state handling;
- reproducibility and independent falsification;
- security hardening;
- institutional, enterprise and agent integration;
- productization, research, legal/IP and operational readiness.

Financing should be staged around evidence rather than feature count.

```text
AGREED GATE
-> EVIDENCE PACKAGE
-> REVIEW
-> NEXT COMMITMENT
```

## Stop 3 — What are the maturity limits?

```text
PRE-D3 = ACTIVE
D3 OPEN = NO
D4 / PRODUCTION = NO
REAL CUSTOMERS = NO
REAL MONEY = NO
```

Rudis should currently be evaluated as a **serious experimental / pre-production architecture under adversarial development**, not as a finished commercial platform.

That distinction is deliberate and part of the diligence model.

## Stop 4 — What does investment not buy?

```text
FUNDING != GOVERNANCE AUTHORITY
INVESTMENT != CANON CONTROL
COMPANY GOVERNANCE != RUDIS CONSTITUTIONAL GOVERNANCE
CAPITAL != CAPTURE
```

A commercial arrangement may create economic, contractual, licensing, evaluation or collaboration rights. It does not automatically create constitutional authority, citizenship, votes, Red Button control, monetary-policy authority or unrestricted Forge access.

## Stop 5 — What evidence should an investor ask for?

A useful diligence sequence is:

```text
PUBLIC THESIS
-> PUBLIC ARCHITECTURE
-> MATURITY / SECURITY BOUNDARIES
-> SANITIZED EVIDENCE
-> PURPOSE-BOUND RESTRICTED REVIEW IF JUSTIFIED
-> INDEPENDENT REPRODUCTION / ATTACK
```

Do not ask first whether every component exists. Ask whether the important claims have **clear falsifiers, reproducible evidence and honest boundaries**.
